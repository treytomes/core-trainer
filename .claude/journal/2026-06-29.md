## Learning

- **Core Wars concepts**: This was a fresh implementation of a Core Wars simulator (MARS - Memory Array Redcode Simulator)
  - Core Wars is a programming game where warrior programs battle in shared memory
  - Warriors are written in Redcode, an assembly-like language
  - The goal is to terminate opponent processes while keeping your own alive

- **Key architectural decisions**:
  - Used C# records for immutable `Instruction` type with `with` expressions for modifications
  - Implemented process queues (one per warrior) for handling SPL (split) instructions that create new execution threads
  - Memory wraps around using modulo arithmetic: `((address % size) + size) % size`
  - Round-robin execution: each warrior executes one instruction per cycle

- **Redcode execution model**:
  - Instructions execute sequentially unless jump opcodes redirect flow
  - DAT instruction kills the executing process (used as "bombs")
  - SPL creates a new process at target address, enabling parallel execution
  - Addressing modes make warriors more dynamic (indirect allows pointer-following)

- **Classic warrior strategies observed**:
  - **Dwarf**: Uses indirect addressing to bomb locations, increments a pointer to spread bombs
  - **Imp**: Minimal one-instruction warrior that creates a trail of copies

## Reflections

### What went well
- Clean separation of concerns with record types for instructions and class-based simulation
- The simulator works correctly out of the gate - Dwarf vs Imp battles run to completion
- Good use of enums for OpCode and AddressingMode makes code readable
- Batch scripts make it easy for Windows users to run without knowing .NET CLI

### What could be improved
- MUL, DIV, MOD, and SLT opcodes are defined but not implemented in `Mars.ExecuteInstruction()`
- No validation when loading warriors (could overwrite each other if loaded too close)
- Process queue is fixed to 2 warriors - could be more flexible
- No way to observe battle progress (runs silently until completion)
- Could benefit from unit tests for instruction execution

### Blockers or concerns
- None currently - the MVP is functional and ready for enhancements
- Need to decide on parser format (original ICWS '94 format vs simplified syntax)
